# 实现与验证状态

> 历史归档：保留 2026-10-27 的实现与验证记录，不作为当前操作指南。当前步骤见[插件市场维护指南](../PLUGIN_SECURITY.md)。

记录日期：2026-10-27。

## GitHub 市场已上线

- 作者手动提交公开 Release 申请；首次发布和更新都需要人工批准，不自动发现新 Release。
- 固定源码提交、ZIP 大小和摘要校验、安全解压、manifest 与 Python 依赖声明检查。
- 使用仓库内置 AST 规则分析组件类型，不执行待审插件，也不在市场安装第三方库。
- AI 阅读归档内完整文本文件并生成报告；缺少文件、存在不可读内容或超出限额时不能宣称审核完成。
- 维护者通过 `/approve` 或 `/reject` 作出决定，保留批准及拒绝记录；普通评论不触发审核。
- 批准时再次核对申请、规则、提示词、已展示的报告、固定提交及下载摘要，防止审核后内容变化。
- 允许包含安全默认值的根目录 `config.toml`，检查 TOML 格式；根目录 `.env` 仍禁止发布。
- 普通下架、恢复，以及版本安全封禁、解除封禁均已提供独立入口。
- 签名私钥保存在 Actions Secret，公钥与通知已发布。首次启用可由 `python -m market.security_setup` 自动完成，以后可直接运行“启用安全通知”工作流。
- 安装包所需公钥配置会自动导出到 `client_config/plugin_market_security_keys.json`。

正式 Release 申请、人工批准及市场目录发布已有线上验证和实际版本记录。静态审核通过不代表插件功能已经运行验证。

## 本轮代码清理

- 在工作流准备环境前过滤不含管理指令的普通评论；正式指令仍需完整匹配并通过权限检查。
- 批准、拒绝不再临时标为“检查中”；新申请和申请编辑仍显示检查进度。
- 合并重复的可信审核评论筛选逻辑，不再累计保存全部历史报告；批准阶段仍重新读取最新报告。
- 普通辅助类及已知标准库辅助类的继承不再产生无关组件提示；动态绑定和未知外部继承仍保留提示。

## 客户端后续工作

主程序的依赖补装、配置迁移、安装回滚和安全隔离已有本地实现及离线测试。本次仅发布 GitHub 市场：

- GitLab 主程序发布、客户端安装包接入公钥配置、实际客户端部署及服务重启另行安排。
- 前端提示、真实版本更新、加载失败恢复和重启隔离仍需在独立部署环境完成浏览器联调。
- 插件间依赖不会自动连带安装；缺失或版本不符仍由运行时报告。
- 自动补装 Python 库只处理缺失库，沿用已有版本，并在补装时约束已有库；共享 Python 库不随插件回滚。

离线客户端收不到新封禁。插件与主程序共用进程和权限，隔离通知不能替代进程沙箱，也不能撤销已经发生的密钥泄露。
